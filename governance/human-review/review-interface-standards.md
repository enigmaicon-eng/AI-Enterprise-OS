# Review Interface Standards

## Purpose
Defines the standard interface presented to human reviewers when they open any approval, escalation, or exception item. Consistency reduces reviewer cognitive load, speeds decision-making, and ensures no critical context is missed. All review interfaces in the enterprise must follow these standards.

---

## Review Interface Principles

1. **Decision-first layout** — The action the reviewer must take is always at the top, never buried
2. **Context before detail** — Summary → analysis → evidence; reviewer should understand the situation before seeing raw data
3. **AI assistance visible** — AI analysis is shown but clearly labeled as AI-generated; never presented as fact
4. **Risk prominently displayed** — Risk level and reversibility shown in header; never de-emphasized
5. **One-click access to history** — Similar past decisions accessible without leaving the review screen
6. **SLA always visible** — Remaining time shown prominently; goes red when < 25% remains
7. **Mandatory rationale** — Rejection always requires rationale; approvals require it for Tier-3+

## Context Panel Definitions

### AI Analysis Panel
```yaml
ai_analysis_panel:
  label: "AI ANALYSIS"
  always_shows:
    - generating_agent_id
    - confidence_score
    - generation_timestamp
  content:
    - situation_summary: 2–3 sentences
    - key_findings: bullet list (max 5)
    - primary_risks: bullet list (max 3)
    - ai_recommendation: APPROVE | APPROVE_WITH_CONDITIONS | REJECT | NEEDS_INFO | ESCALATE
    - recommendation_confidence: float
  
  display_rules:
    confidence < 0.60: show "LOW CONFIDENCE — treat as informational only" warning
    confidence >= 0.90: show "HIGH CONFIDENCE" indicator
    no_ai_available: show "No AI analysis available for this request type"
  
  disclaimer: "AI analysis is advisory only. Your decision is authoritative."
```

### Constitutional Pre-Check Panel
```yaml
constitutional_panel:
  label: "CONSTITUTIONAL PRE-CHECK"
  always_shows:
    - verdict: PASS | CONDITIONAL | FAIL | PENDING | NOT_RUN
    - confidence
    - check_timestamp
  
  conditional_content:
    verdict == CONDITIONAL:
      show: conditions_list + acknowledgment_required checkbox
    verdict == FAIL:
      show: CRITICAL banner + violated_principles + auto_escalation_notice
    verdict == PENDING:
      show: "Evaluation in progress — you may review other context while waiting"
  
  if_not_run:
    show: "Constitutional check not required for this request type"
```

### Similar Past Decisions Panel
```yaml
similar_decisions_panel:
  label: "SIMILAR PAST DECISIONS"
  query:
    match_on: [subject.type, subject.risk_level, relevant_policies]
    limit: 5
    sort_by: similarity_score DESC
  
  display_per_item:
    - request_title
    - decided_at: relative time (e.g., "3 months ago")
    - decided_by: role (not name, for privacy)
    - outcome: APPROVED | REJECTED | APPROVED_WITH_CONDITIONS
    - key_rationale: first 100 characters
    - outcome_follow_up: "outcome was later: [positive/negative/neutral]" if known
  
  interaction: click any item to expand full record
```

## Decision Action Specifications

### APPROVE
```yaml
action: APPROVE
requires_rationale: tier >= 3
signature_required: true   # Ed25519
confirmation_dialog: false for tier 1–2; true for tier 3+ ("You are approving a {risk_level} action")
post_action:
  - record decision in audit trail
  - release holds if any
  - advance workflow
  - notify submitter
```

### APPROVE WITH CONDITIONS
```yaml
action: APPROVE_WITH_CONDITIONS
requires_conditions: true (at least 1, max 10)
requires_rationale: always
confirmation_dialog: true
condition_types:
  - MUST_IMPLEMENT: specific implementation requirement
  - MUST_NOTIFY: notification to specific party required
  - TIME_LIMITED: approval valid only until specified date
  - REQUIRES_REVIEW: must come back for re-review after N days
post_action:
  - record conditions in approval record
  - conditions published to workflow context
  - workflow continues with conditions attached
```

### REQUEST INFO
```yaml
action: REQUEST_INFO
requires_questions: true (at least 1)
pauses_sla_clock: true (during info-gathering period)
max_info_rounds: 3 (then auto-escalate)
notification: submitter notified with questions
```

### REJECT
```yaml
action: REJECT
requires_rationale: always
min_rationale_length: 20 characters
confirmation_dialog: true
revision_window:
  grant_revision: true/false (reviewer chooses)
  revision_deadline: reviewer sets (max 30 days)
post_action:
  - record rejection + rationale
  - notify submitter with rationale
  - do NOT advance workflow
```

### DELEGATE
```yaml
action: DELEGATE
requires_delegate_selection: true
requires_rationale: true
constraints:
  - delegate must have tier >= request.tier_required
  - delegate must not be in exclude_approvers list
  - conflict_of_interest check re-run for delegate
audit: delegation logged as APPROVAL_DELEGATED event
```

### ESCALATE
```yaml
action: ESCALATE
requires_rationale: true
auto_routes_to: next tier queue
handoff_package: generated automatically
use_when: request beyond current reviewer's authority or expertise
```

## Rationale Quality Check

Before submitting, rationale is checked:

```yaml
rationale_quality:
  min_length: 20 characters
  max_length: 2000 characters
  
  quality_checks:
    - not_only_whitespace
    - not_generic_placeholders: ["ok", "approved", "looks good", "fine", "yes"]
    - addresses_specific_concern: for REJECT and APPROVE_WITH_CONDITIONS
  
  ai_quality_score:
    run: always
    if_score < 0.60 (low quality):
      show: "Your rationale appears brief. Consider addressing: [specific concerns from context]"
      block: false   # warning only, not blocking
    if_score < 0.40 (very low quality):
      show: same warning
      block: tier >= 3   # for senior reviewers, require meaningful rationale
```

## Accessibility and Performance Standards

```yaml
performance:
  interface_load: < 2 seconds (all context panels loaded)
  decision_submission: < 500ms acknowledgment
  
accessibility:
  keyboard_navigation: full keyboard support
  screen_reader: ARIA labels on all decision elements
  mobile: responsive layout for on-call approvals
  
offline_resilience:
  draft_decisions_cached: true
  submit_when_reconnected: true
  conflict_detection: if state changed while offline, show diff before submitting
```
