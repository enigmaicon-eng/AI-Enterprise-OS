# Change Authorization Matrix

**Component:** RSI-GOV-002 | **Owner:** Meta-Org | **Tier:** T4 | **Class:** CRITICAL

## Role
Defines exactly who can authorize each type of improvement proposal, what evidence is required, what the approval workflow looks like, and what happens when the required authorizer is unavailable. This is the binding governance contract for the improvement system — no improvement may be applied without matching an entry in this matrix.

## Evidence Requirements by Tier

### AUTO Tier
```
REQUIRED EVIDENCE:
  safety_check_result: APPROVED (all 5 checks PASS or CONDITIONAL resolved)
  blast_radius: LOCAL or MODERATE only (WIDE+ escalates to T3)
  rollback_procedure: defined and estimated time < 5 min
  
NO HUMAN ACTION REQUIRED. Logged automatically.
```

### T2 Tier
```
REQUIRED EVIDENCE:
  safety_check_result: APPROVED
  change_description: specific, complete (not vague)
  expected_outcome: stated with measurable metric
  rollback_procedure: defined
  
AUTHORIZATION WORKFLOW:
  1. Proposal generated by improvement-planner
  2. Safety check run automatically
  3. If APPROVED: notification sent to T2 authorizer with 48-hr response window
  4. T2 authorizer: reviews proposal summary → ACK (proceed) | REJECT (reason required)
  5. ACK recorded in audit trail; change applied within next deployment window
  6. REJECT: returned to planner with reason; 1 revision allowed
```

### T3 Tier
```
REQUIRED EVIDENCE:
  safety_check_result: APPROVED
  problem_statement: root cause + impact quantification
  proposal_detail: specific change with before/after comparison
  forecast: ROI > 2.0; forecast range (pessimistic/base/optimistic)
  implementation_plan: phases, timeline, resource estimate
  rollback_procedure: tested; automated; < 30 min
  data_evidence: for gate threshold adjustments — 30d of baseline data required
  shadow_test_results: for algorithm changes — 30-day comparison required
  
AUTHORIZATION WORKFLOW:
  1. Proposal package assembled by improvement-planner + impact-forecaster
  2. Safety check run; blast radius computed
  3. If APPROVED: proposal submitted to T3 authorization queue
  4. T3 authorizer reviews within SLA (72 hr default)
  5. T3 may: APPROVE | APPROVE_WITH_CONDITIONS | REQUEST_REVISION (once) | REJECT
  6. APPROVE_WITH_CONDITIONS: conditions logged; planner must satisfy before apply
  7. REQUEST_REVISION: author has 5 business days to revise and resubmit
  8. Approved T3 changes applied in next scheduled deployment window
```

### T4 Tier
```
REQUIRED EVIDENCE:
  All T3 requirements PLUS:
  business_case: strategic alignment + business impact quantification
  risk_assessment: full blast radius + mitigation plan
  stakeholder_impact: list of all affected teams + consultation record
  legal_review: if org structure or compliance changes (DPO/Legal sign-off)
  pilot_plan: for significant changes — pilot with 1 team before broad rollout
  communications_plan: how change will be announced + managed
  
AUTHORIZATION WORKFLOW:
  1. Proposal package with all required evidence assembled
  2. Safety check (full 5-check battery)
  3. Proposal enters T4 review queue
  4. Pre-review meeting scheduled (within 1 week of submission)
  5. T4 panel review (VP Engineering + required co-authorizer)
  6. Decision: APPROVE | APPROVE_WITH_PILOT | STAGED_APPROVAL | REJECT
  7. STAGED_APPROVAL: first stage authorized; subsequent stages require check-in
  8. Implementation begins after all required authorizers sign; logged
  9. Post-implementation review required at T+30d
```

### T5 Tier
```
REQUIRED EVIDENCE:
  All T4 requirements PLUS:
  constitutional_alignment_review: written analysis of constitutional impact
  regulatory_counsel_sign_off: for compliance-affecting changes (DPO + external legal)
  external_audit_report: for safety controller / authorization matrix changes
  board_briefing: for any change requiring Board awareness
  scenario_analysis: what happens if this change has unintended effects?
  
AUTHORIZATION WORKFLOW:
  1. Full proposal package assembled by T4 sponsor
  2. Pre-read package distributed ≥ 1 week before decision meeting
  3. T5 decision meeting (CEO + CTO + required third party)
  4. Decision recorded with individual votes and rationale
  5. Implementation plan reviewed and approved in same session
  6. Post-implementation audit at T+90d; results reported to Board
```

## Unavailability Protocols

```
AUTHORIZER UNAVAILABLE:
  AUTO/T2: no substitute needed; automated or backup PM Lead
  T3: alternate Engineering Director (backup roster maintained)
  T4: VP Engineering → CTO (if VP unavailable); cannot proceed without quorum
  T5: cannot proceed without required authorizers; escalate to schedule emergency session

ESCALATION IF SLA BREACHED:
  T2 SLA breached: auto-escalate to T3 authorizer
  T3 SLA breached: alert VP Engineering; flag in governance dashboard
  T4 SLA breached (urgent proposal): CTO may invoke T4 emergency authorization
  T5: no escalation path; T5 SLA is a firm timeline (must schedule)

EMERGENCY AUTHORIZATION (Production Safety Only):
  Scope: changes required to prevent active production incident or regulatory breach
  Authority: T3 emergency auth allows immediate apply with T4 post-review within 48hr
  T4 emergency auth: CTO + VP Engineering verbal approval; written record within 2hr
  Limitations: CANNOT emergency-authorize constitutional changes, matrix changes, or
               safety controller modifications under any circumstances
```

## Authorization Record Schema

```yaml
authorization_record:
  proposal_id: IMP-{YYYY-MM-DD}-{NNN}
  authorization_tier: AUTO | T2 | T3 | T4 | T5
  required_authorizers:
    - role: string
      name: string
      decision: APPROVED | APPROVED_WITH_CONDITIONS | REJECTED
      decision_timestamp: ISO8601
      conditions: list of strings | null
      rationale: string
  quorum_met: boolean
  authorization_timestamp: ISO8601
  conditions_outstanding:
    - condition: string
      resolved: boolean
      resolved_timestamp: ISO8601 | null
  authorization_valid_until: ISO8601 (30 days from auth; must re-authorize if not applied)
  emergency_flag: boolean
  emergency_rationale: string | null
  post_review_required: boolean
  post_review_due: ISO8601 | null
```

## Matrix Integrity Controls

```
IMMUTABILITY RULES:
  This matrix cannot be modified without T5 authorization (CEO + CTO co-sign)
  Any proposal to lower authorization tiers = Hard Deny HD-005
  Any proposal to add bypass paths = Hard Deny HD-007
  Any proposal to allow AI self-authorization at T4+ = Hard Deny HD-009

AUDIT:
  All authorization decisions: permanent record in improvement-audit-trail.md
  Monthly review: VP Engineering confirms no unauthorized changes to matrix
  Quarterly review: CTO + external auditor confirm matrix integrity
  SHA-256 hash of this file stored in improvement-audit-trail.md on every change

ENFORCEMENT:
  Change application system checks authorization_record before applying
  If authorization_record absent or expired: change BLOCKED; alert T4
  If quorum_met = false: change BLOCKED; alert T4
```
